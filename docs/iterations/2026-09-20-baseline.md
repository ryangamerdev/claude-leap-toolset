# 2026-09-20 — Retrospective baseline and repository checkpoint

## Scope and evidence boundary

This entry reconstructs the accumulated development history from retained research reports,
source changes and session notes. It is not a contemporaneous log of every earlier edit.
The user requested this checkpoint and a detailed rationale for every subsequent iteration.
[FEATURES](../FEATURES.md) remains the feature/status inventory and [PLAN](../PLAN.md) the
acceptance order. No broad Sky parity or certification is claimed.

The objective is reliable native operation at least as effective as Sky, demonstrated first
in Gameday, then iPhone/iPad Simulator and a paired Blender basic-shape Mickey-head exercise.
The MCP should perform observation, evidence retention and routine validation internally,
returning compact useful results while allowing deeper investigation. A companion TUI is deferred.

## 1. Connection reliability and schema diagnosis

Earlier reports of stale Claude tool schemas were not sufficient evidence of a stale live
server: a fresh ToolSearch eventually returned the current definitions. Do not infer a
proven persistent-cache cause or universal cache-clearing remedy from those reports.
A separate, concrete Codex connection issue involved object-valued experimental capabilities
in initialize versus the Swift SDK's string-valued representation.

`CompatibleTransport` normalizes unsupported experimental values only at initialization.
This preserves the installed registration name `leap` and avoids a name-change workaround
that would hide the compatibility issue. The tradeoff is intentionally ignoring unsupported
experimental metadata rather than interpreting it. `scripts/test-mcp-handshake.py` retains
protocol regression coverage; stdio harness results are distinct from native MCP acceptance.

## 2. Targeted pointer delivery and scroll routing

Field gestures exposed foreground/background differences, interference from the user's
mouse, and apparent window movement instead of field movement. A foreground-only workaround
would disrupt the user and leave background operation unreliable. The Sky reference was
examined to understand window/process targeting; it is extracted reference material, not
original source. An earlier inference from missing imports was corrected because dynamically
resolved APIs exist in that reference.

Leap now routes pointer operations using target window identity, local coordinates and
process-targeted events with synthetic focus. This addresses event destination rather than
assuming a second virtual mouse is required. Visible pointer feedback is retained because
the user values it. Wheel routing also required the reference's special field-51 behavior.
Keyboard fallback can still differ; universal foreground/background parity is not established.

[Field](../research/trial-field-details.md), [scroll](../research/trial-scroll-details.md)
and [navigation](../research/trial-navigation-details.md) reports retain the scoped evidence.
Gameday field pan/zoom/reset and half-page scrolling have recorded passes. Those passes do
not imply equivalent behavior in Simulator or Blender, whose paired campaigns remain pending.

## 3. Ambiguous accessibility acknowledgements must not duplicate actions

The critical editor incident was a Save that persisted data and closed the editor but
returned an accessibility error. Treating every failed AXPress acknowledgement as permission
to send a coordinate click can execute a second, unrelated action after the UI changes.
In particular, `cannotComplete` (-25204) is not proof that nothing happened.

The fallback is restricted to `actionUnsupported`; ambiguous acknowledgements retain
uncertainty and obtain fresh evidence. This deliberately gives up blind retry convenience
in favor of avoiding duplicate writes. [Editor incident](../research/trial-editor-details.md)
and [native Save trial](../research/recording-save-native-trial.md) explain the evidence.
A later native Save reproduced -25204 while a mirrored route persisted through reopening.
The retained record shows one intent/result and no reported fallback, not an independent
OS event-tap proof of all delivered events.

## 4. Durable observations instead of losing evidence between calls

A screenshot or current tree cannot reconstruct an intermediate error or transition.
Repeatedly replaying an action to diagnose it changes conditions and can repeat writes.
The user's Runner and Tracer examples motivated a durable session model: retain richer
observations locally, then query the relevant portion without filling agent context.

Recording uses SQLite under `.leap`, explicit project binding, sessions/interactions/actions,
committed action intents, snapshots, and a dedicated AXObserver thread. WAL and ownership
checks support local storage; bounded event queues produce gap records rather than silently
claiming complete capture. Project Git exclusion is idempotent. Notifications represent
received envelopes, not historic attribute values or proof of causation. Storage has a
256 MiB budget; retention rotation is still a gap.

A plain JSON dump would be easier to inspect initially but weaker for joins and bounded
historical queries. Screenshots alone would miss semantics and consume context. SQLite is
an implementation detail: the agent receives tools and evidence references, not a requirement
to manage database transactions. See [design](../research/observation-session-design.md),
[checkpoint](../research/recording-v1-checkpoint.md) and [native trial](../research/recording-v1-native-trial.md).
Start/stop and historical access have scoped passes. A numeric-expression versus TEXT-cursor
query bug was fixed with explicit casting and verified against retained node ordinals.

## 5. Outcome checks and digestible history

Action acknowledgement and actual state must be reported separately. `verified_action`
combines execution with observation-based checks, while `wait_for` polls internally without
consuming the agent's rendered baseline. Retained expectation records preserve before/after
checks. This avoids requiring the agent to repeatedly fetch an entire tree, while leaving
uncertain outcomes visible rather than converting a timeout into definitive failure.

`recording_review` offers overview, actions, issues and grouped events. Byte caps and stable
through/after pagination bound responses. Node outlines support discovery before detail.
This is preferable to truncating the last few log lines, which can hide the only useful error.
Native expectation transitions and review overview passed scoped cases; complete grouped
pagination acceptance remains pending. See [insights](../research/insights-layer.md) and
[timing review](../research/timing-and-readiness-review.md).

## 6. Integrated UI queries, assets, diffs and joined results

`bind_project` enables automatic application recording; `ui_to_text` exposes filtered UI
state, IDs, fields, depth/subtrees and coordinates. Long AX strings are captured up to a
bounded limit with truncation markers; secure fields are redacted. `leap_asset` retrieves
captured text or materializes files in bounded chunks. This is text/node-field support,
not general binary, screenshot or base64 ingestion. `ui_diff` compares historical snapshots;
`interaction_result` joins action intent, acknowledgement and checks. Ordinary results use
compact rendering and evidence references rather than unbounded JSON dumps.

Readiness uses monotonic read budgets and bounded AX call timeouts, with read-failure,
deadline and cap metadata. Incomplete reads cannot establish a predicate. This is better
than an arbitrary sleep, but cannot guarantee hard cancellation of every OS call or prove
that a visually complex canvas has reached its intended state. Temporal predicates remain
future work. UI coordinates in query JSON are screen-relative; action coordinates are
window-relative, and historical indices need freshness validation.

[Integrated design](../research/integrated-observation-layer.md) and
[native trial](../research/integrated-native-trial.md) distinguish tests from pending cases.
Recorded native evidence includes a Gameday observation of 258 nodes with zero read errors,
a filtered 44-button query, reversible background transitions, joined results, historical
lookup, raw-text/file retrieval from a fixture and review overview. Fixture asset retrieval
does not establish acquisition of a huge real application field. Four focused EvidenceTests
cover asset handling, pagination/references, partial comparisons and joined uncertainty.

## Repository checkpoint and future process

This checkpoint retains source, reusable tests, skills, reports, curated image/text/JSON
results and small install metadata. `.gitignore` excludes runtime stores, database files,
generated nested fixture repositories, Python caches, build logs, downloads, app bundles
and raw recovered scratch history. These remain on disk under the repository; none were
deleted. Database snapshot IDs and fixture paths in reports refer to local-only evidence,
not data available in a fresh clone. Tracked summaries preserve conclusions and limitations.

The README's obsolete claim that recording was merely planned was corrected. `AGENTS.md`
now requires a rationale entry for each implementation/test/install iteration using the
linked template and index. Entries must explain evidence, alternatives, tradeoffs, validation,
build identity and remaining uncertainty. This retrospective establishes a baseline without
inventing missing historical details. Future commit/push authorization is not implied.
